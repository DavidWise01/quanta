# QG-064 — The Trust Anchor

## Boundary

**A hash-verified source registry is not automatically trustworthy.** QG-063 checks packet content against a pinned registry; QG-064 first verifies that registry's Ed25519 signature against a public key supplied as an **independent trust anchor**. No self-declared key from the submitted manifest is accepted as its authority.

```text
             SOURCE REGISTRY
                   |
              SIGNED ENVELOPE
                   |
       TRUSTED PUBLIC KEY (SEPARATE)
                   |
             VERIFY ED25519
             /            \
           PASS           FAIL
            |              |
        REVISION GATE     REJECT
            |
        QG-063 SHA-256
            |
        QG-062 ANCESTRY
            |
        NO AUTO-AUTHORITY
            |
           {{i}}
```

### Deterministic signed payload

An envelope carries `{schema:'QUANTA-QG-064-MANIFEST', revision, registry}`, an SHA-256 digest of its canonical sorted-key JSON serialization, and an Ed25519 signature over **those same canonical bytes**. A public JWK and minimum allowed revision are passed separately to `verifyManifest(envelope, anchor)`. The registry is validated through QG-063 before signing and before verifying. SHA-256 hashes bytes for consistency; Ed25519 verifies that the bytes were signed by the private key paired with the externally trusted public key.

A signature from an unrelated key, tampered ancestry, forged digest or old revision fails before evidence admission. The minimum revision rejects an old signed manifest only when the calling system has already pinned a later minimum. The kernel never obtains its trust key from the untrusted envelope itself.

Following a valid manifest, QG-063 verifies each incoming packet against source identity, digest and declared policy; accepted packets pass through QG-062 connected-ancestry counting. GitHub and 0root.ai remain two owned surfaces sharing one ancestry root, while independent permitted external sources can supply separate roots. Passing these gates **does not automatically restore model authority**; a separate explicit authorization remains required.

### Important limits

The demonstration generates fresh ephemeral Ed25519 keys. It does **not** possess genuine publishing keys for GitHub, 0root.ai or external websites; it does not prove publisher identity or that any site agreed to its contents. The independent public-key trust anchor is assumed to have been obtained securely by the caller; this is the root of trust, not a proof generated by the manifest itself. A malicious actor who controls the externally pinned key or can replace the entire local state can still forge a consistent ledger. No external immutable timestamp, certificate chain, transparency log, real-time robots/llms check or live crawl is included.

Ed25519 authenticates the key relationship, not the reliability of the report's factual assertions, not the independence of external evidence and not permission to republish gated content. The synthetic signed manifest and admission ledger are deterministic and replay-verifiable but are not an actual deployed security system.
